# QA do front-end — 14/11/2026

Base: `origin/main` em `56a0bab`, com as alterações na branch `front-dev3`.
Aplicação local, API FastAPI e motor real, com o talhão de demonstração.
Os testes de navegador criam contextos descartáveis: não usam nem apagam o
rascunho do navegador pessoal. Não houve publicação ou alteração dos dados agronômicos.

## Correções desta rodada

| Problema encontrado | Comportamento corrigido | Evidência de regressão |
|---|---|---|
| Enter não acionava botões como “Adicionar ao histórico”; só Espaço funcionava | Convenções de teclado web habilitadas em todos os controles Rune | Fluxo de formulário com Tab e Enter |
| Abrir um Select esvaziava toda a árvore acessível | O espelho DOM alcança a lista dentro do modal sem incluir seu fundo | Seleção por teclado e opções acessíveis |
| Campos eram chamados “Text input”, havia um campo de senha sem uso e botões desabilitados pareciam disponíveis na árvore | Nomes dos campos em foco, ocultação dos proxies inativos, estado desabilitado, alertas, títulos e região principal | Inspeção semântica no navegador |
| Um item `null` no histórico impedia a restauração do rascunho inteiro | Restauração independente de contorno, histórico e opções; aviso quando algo precisa de revisão | Testes unitários e recarregamento com rascunho parcialmente inválido |
| Restauração aceitava safras que o formulário rejeitava | Mesmas regras de ano e safra consecutiva na recuperação | Casos válidos/inválidos, incluindo virada de século |
| Coordenadas brasileiras como `-20,032; -48,526` eram rejeitadas | Vírgula decimal com ponto e vírgula ou espaço; formato com ponto continua válido | Testes de parsing e localização no mapa |
| Uma reconexão antiga podia substituir a mais recente | Cancelamento e identificação das tentativas de conexão | Falha atrasada após reconexão bem-sucedida |
| Erros HTTP com corpo nulo podiam expor um TypeError | Erros de serviço/contrato continuam legíveis mesmo com corpo malformado | Testes de respostas nulas e inválidas |
| “Concluir desenho” estava disponível fora do modo de desenho; valores antigos podiam ficar visíveis após invalidar um contorno | Estados dos botões sincronizados; área/GeoJSON inválidos não exibem o valor anterior | Desenho, edição, cancelamento e reabertura |
| Nome longo competia com o número de hectares em telas estreitas | Nome e área empilhados em tela pequena ou com nome longo; cabeçalho pode quebrar linha | Capturas em 320 e 900 px |
| Resumos mostravam hectares com ponto decimal | Vírgula decimal também nos resultados e na timeline | Revisão visual |
| Falha de inicialização mostrava comandos de desenvolvimento | Mensagem para o usuário com botão “Recarregar página” | Falha simulada no download WASM e recuperação |

O patch de acessibilidade é versionado em
`patches/rune-web-accessibility.patch`, na revisão Rune já fixada pelo projeto.
`scripts/setup-rune.mjs` aplica o patch de forma idempotente. Não é uma atualização
da biblioteca nem uma certificação de acessibilidade.

Foi acrescentado `npm run build:release`: no PowerShell deste ambiente, a chamada
anterior com argumentos encaminhados pelo npm gerou o perfil de desenvolvimento.
O comando explícito foi conferido pelo log `Finished release profile [optimized]`.

As 24 combinações HTTP incluem 7 respostas vazias válidas e 5 timelines que

A passagem final dos três cenários passou na distribuição otimizada, servida
pelo Vite preview em `127.0.0.1:4174`, com Chrome **157.0.8103.52**. Os resultados
detalhados dessa execução estão nos arquivos locais `output/playwright/*-final.json`.

Fluxo principal: início vazio, exemplo, cancelar/confirmar mapa, histórico,
validação, duplicidade, reordenação, remoção, restauração, seleção de mês/horizonte,
resultado vazio, motivos de descarte, três cards reais, etapas e ano seco,
retorno à configuração e confirmação/cancelamento da limpeza.

Falhas: metadados indisponíveis, reconexões concorrentes, HTTP 503, JSON inválido,

Mapa: geolocalização autorizada com posição emulada, recusa simulada, desenho por
toque, rejeição com apenas dois vértices, edição por arraste, cancelamento do
desenho substituto e preservação da área confirmada.

Layout: **320, 360, 390, 768, 900, 1024, 1440 e 1920 px**, incluindo nome longo e
histórico com 12 registros. A checagem automática confere limites horizontais dos
controles e do diálogo; capturas complementam a inspeção visual. Não equivale a
uma comparação pixel a pixel de todas as posições de rolagem.

Build otimizado, formatação Rust e `git diff --check` também conferidos.
Capturas locais em `output/playwright/`, ignoradas pelo Git.

## Repetir

Na pasta `frontend/`:

```powershell
npm test
npm run test:rust
npm run build:release
npm run dev
# Em outro terminal, com API e front ativos:
npm run test:integration
```

Da raiz, com Chrome disponível e o site ativo, abrir uma sessão Playwright CLI:

```powershell
npx --yes --package @playwright/cli playwright-cli -s=qa open http://127.0.0.1:4173
npx --yes --package @playwright/cli playwright-cli -s=qa --raw run-code --filename=frontend/tests/browser-qa.js
npx --yes --package @playwright/cli playwright-cli -s=qa --raw run-code --filename=frontend/tests/browser-resilience.js
npx --yes --package @playwright/cli playwright-cli -s=qa --raw run-code --filename=frontend/tests/browser-map-layout.js
npx --yes --package @playwright/cli playwright-cli -s=qa close
```

Para testar a distribuição, iniciar `npm run preview` no lugar de `npm run dev`.
`npm test` executa os testes unitários; os três cenários de navegador acima são
separados e precisam do serviço ativo.

## Limites e próximos alvos

- Navegador Chromium no Windows; toque e tamanhos de celular são emulados.
  Não há validação em aparelho físico ou Safari/iOS nesta rodada.
- Acessibilidade conferida por teclado e árvore semântica. Falta escuta com
  NVDA/VoiceOver; o runtime ainda representa controles em canvas e os campos de
  texto dependem do proxy do campo em foco. Não há alegação de conformidade WCAG.
- Erros de rede, permissão, quota e timeout foram provocados por interceptação
  no contexto de teste. O timeout foi encurtado somente no teste; não houve
  espera real de seis minutos. Não foram executados scripts de coleta NASA.
- Não foram testados carga simultânea, todas as combinações de GPU/driver,
  todos os fallbacks gráficos ou um deploy público.
- O bundle JS permanece perto de 508 kB e o WASM otimizado perto de 15,9 MB,
  antes de compressão de transporte. Carregamento em rede móvel lenta é um
  alvo prioritário de otimização; esta rodada não comprova esse desempenho.
- Avisos de código nativo não utilizado do Rune e depreciação do TestClient
  continuam presentes. Não impediram os testes nem o build.
